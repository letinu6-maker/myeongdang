# 건수 검증표

- 작성: 박준영 (데이터 담당)
- 실행: `python src/clean.py` (자동 기록은 `reports/count_check_auto.md`)
- 기준 데이터: 서울시 외국인관광도시민박업 인허가 정보(OpenAPI, 2026-11-24 수집), [단기외국인] 행정동별 서울 생활인구(250m) 2026-10-01~10-31

## 1. 도시민박업 인허가

| 단계 | 원본 | 제거 | 정리 후 | 확인 방법 |
|---|---:|---:|---:|---|
| 수집 | 9,784 | – | 9,784 | API가 알려 준 전체 건수(list_total_count) 9,784건과 받은 행 수가 같음 |
| 중복 제거 | 9,784 | 0 | 9,784 | 구청코드(OPNSFTEAMCODE)+관리번호(MGTNO) 기준. 관리번호는 구청마다 따로 매겨져서, 관리번호만 기준으로 삼으면 서로 다른 업소 6,930건이 중복으로 잘못 지워짐 |
| 영업 중만 남기기 | 9,784 | 1,951 | 7,833 | 폐업 1,859 + 취소·말소·만료·정지·중지 69 + 휴업 23 = 1,951 |
| 자치구 매칭 | 7,833 | 0 | 7,833 | 도로명주소(없으면 지번주소)에서 '서울특별시 ○○구'를 추출함. 매칭 성공 7,833 + 실패 0 = 7,833 |

- 계산 확인: 9,784 − 0 − 1,951 = **7,833**
- 객실 수: 영업 중 7,833곳 중 3,601곳(46%)이 비어 있음. 자치구별 결측률이 10%~99%로 차이가 커서 값을 채우지 않았고, 경쟁 지표로는 **영업 중 업소 수**를 사용함.

## 2. 단기외국인 생활인구

| 단계 | 원본 | 제거 | 정리 후 | 확인 방법 |
|---|---:|---:|---:|---|
| 수집 | 317,688 | – | 317,688 | 일별 파일 31개 × 10,248행(행정동 427개 × 24시간) = 317,688 |
| 자치구 매칭 | 317,688 | 0 | 317,688 | 행정동코드 앞 5자리를 자치구 코드로 사용. 매칭 성공 317,688 + 실패 0 = 317,688 |
| 자치구 요약 | 317,688 | – | 25 | 날짜·시간별로 구 합계를 낸 뒤, 밤(0~5시)과 낮(10~17시) 시간대 평균을 계산함 |

- 파일 형식: 31개 중 27개는 데이터 줄이 세미콜론으로 구분되고, 4개(10·11·13·14일)는 쉼표로 구분됨. 줄마다 구분자를 판단해서 읽었고, 두 형식 모두 10,248행으로 같음을 확인함.
- 비공개('*') 칸: 생활인구합계 컬럼에는 0건이었음.

## 3. 최종 결합

| 항목 | 값 | 확인 방법 |
|---|---:|---|
| 서울 자치구 기준표 | 25 | 행정 코드 25개 |
| 생활인구가 없는 자치구 | 0 | 25개 구 모두 값이 있음 |
| 도시민박업이 0곳인 자치구 | 0 | 25개 구 모두 1곳 이상 |
| 최종 행 수 | **25** | 기준표 25 = 매칭 성공 25 + 실패 0 |
| 업소 수 합계 | 7,833 | district_summary.csv의 active_listings 합계가 1단계의 정리 후 건수와 같아야 함 |

## 4. 외부 대조 (표본 점검)

- 업소명으로 에어비앤비를 검색한 결과, 20곳 중 확인된 곳은 1곳뿐이었음. 인허가에 등록된 상호와 숙소 제목이 대부분 다름.
- 에어비앤비 숙소 페이지에 공개된 등록번호가 관리번호 끝 10자리와 같아서, (발급 구 + 등록번호)로 1:1 매칭됨. 표본 1: 등록 객실 4실, 에어비앤비 표기 3 rooms로 근접하게 일치함.
- 한계: 에어비앤비에는 공유숙박 실증특례로 등록된 숙소도 있는데, 이런 곳은 이 인허가 데이터에 없음. 따라서 실제 경쟁 숙소 수는 데이터에 잡힌 것보다 많을 수 있음.
