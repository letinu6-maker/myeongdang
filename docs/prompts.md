## 2026-11-24 · 박준영 · 도시민박업 객실 수 결측 원인 확인
- 요청: 영업 중 업소의 객실 수(STROOMCNT)가 절반 가까이 비어 있는 이유를 찾고, 업소당 객실 1개로 채워도 되는지 물어봄.
- 결과: AI가 영업상태별·인허가 연도별·자치구별 결측률을 뽑는 코드를 제안함. 실행해 보니 자치구별 결측률이 중구 10%부터 동작구 99%까지 크게 달랐음.
- 확인·수정: 구청마다 입력 습관이 달라서 생긴 결측으로 판단함. 1실로 채우면 결측이 많은 구의 경쟁 정도가 낮게 잡히는 편향이 생기므로, 경쟁 지표를 객실 수 합계에서 영업 중 업소 수로 바꿈.
- 배운 점: 결측을 채우기 전에 결측이 어디에 몰려 있는지 먼저 확인해야 함.

## 2026-11-24 · 박준영 · 중복 제거 키 오류 발견
- 요청: 공공데이터의 객실 수가 실제와 맞는지 보려고 에어비앤비 숙소와 대조해 달라고 함.
- 결과: 업소명으로는 표본 20곳 중 1곳만 찾을 수 있었음. 에어비앤비 숙소 페이지에 공개된 등록번호(예: 2017-000022)가 관리번호(MGTNO) 끝 10자리와 같다는 점을 이용해 1:1로 매칭함. 대조 결과 등록 객실 4실, 에어비앤비 표기 3 rooms로 근접하게 일치함.
- 확인·수정: 같은 관리번호가 중구·종로구·용산구·마포구에서 서로 다른 업소로 나왔음. 관리번호는 구청마다 따로 매겨지는 번호였음. AI가 처음 작성한 clean.py는 관리번호만 기준으로 중복을 지웠는데, 실제 데이터로 확인해 보니 이 방식이면 9,784건 중 6,930건(약 70%)이 잘못 지워짐. 중복 제거 키를 구청코드(OPNSFTEAMCODE)+관리번호로 고치자 진짜 중복은 0건이었음.
- 배운 점: AI가 제안한 고유키도 실제 데이터로 중복 여부를 직접 확인해야 함. 이름처럼 보이는 키보다 공식 번호로 외부 데이터와 대조하는 편이 정확함.
