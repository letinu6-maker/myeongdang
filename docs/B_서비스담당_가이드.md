> 이 파일은 B(서비스 담당) 김태현과, 김태현이 쓰는 AI 코딩 에이전트(Claude Code 등)가 함께 읽는 작업 지시서입니다.
> **에이전트를 처음 실행하면 이 파일 전체를 먼저 읽게 하세요.** 마지막 절에 첫 프롬프트 예시가 있습니다.
> 작성: 박준영(A, 데이터 담당) · 2026-11-24 기준 v2

**v2에서 바뀐 점 (11/20 제출 후 교수님 피드백 반영)**
- 1차 범위를 **도시민박업 인허가(API) + 단기외국인 생활인구(CSV)** 두 가지로 줄였습니다. 전월세 실거래가는 **여유가 있을 때 추가하는 2차 목표**입니다.
- 그래서 손익분기 계산의 월세는 **사용자가 직접 입력**합니다. 신규 호스트는 자기 집 월세를 이미 알고 있으므로 오히려 자연스러운 설계입니다.
- CSV 스키마에서 월세 컬럼이 빠졌고, `/rank`의 `max_rent` 대신 `max_rooms`(경쟁 객실 수 상한)를 씁니다.

## 1. 프로젝트 한눈에

**과목 과제:** "AI개발환경의 이해" 기말 팀 프로젝트. 경영 질문 하나에 공공데이터로 답하는 작은 웹 서비스를 만듭니다. 필기시험 대신 이 프로젝트와 발표로 평가합니다.

**팀명·서비스명:** 명당발견
**주제:** "외국인 관광객 숙소, 서울 어느 구에서 시작해야 본전을 찾을까?"
**사용자:** 외국인관광 도시민박업 등록을 준비하는 예비 에어비앤비 호스트(개인 사업자)

**서비스가 하는 일**
1. **입지 비교:** 서울 25개 자치구를 외국인 숙박 수요와 경쟁 숙소 수로 비교해 순위를 보여 줍니다.
2. **손익분기 계산:** 사용자가 1박 요금, 예상 가동률, 월세, 월 기타 비용을 넣으면 "한 달에 최소 며칠 예약돼야 본전인지"와 예상 월 손익을 보여 줍니다.

**쓰는 데이터 (A가 수집·정리)**
| 데이터 | 형태 | 용도 |
|---|---|---|
| 외국인관광 도시민박업 인허가 정보 | 서울 열린데이터광장 OpenAPI | 경쟁 숙소: 영업 중 업소 수·객실 수 |
| [단기외국인] 행정동별 서울 생활인구(250m) | 서울 열린데이터광장 월별 CSV | 외국인 수요: 야간(숙박)·주간(관광) |
| (2차) 국토교통부 전월세 실거래가 | 공공데이터포털 OpenAPI | 자치구별 월세 참고값. 여유 있을 때만 |

생활인구 데이터는 이름에 "250m"가 있지만, 250m 격자 자료를 **행정동별로 집계해서 제공하는 자료**입니다. A가 행정동 값을 자치구로 합산합니다.

**B는 원본 데이터를 직접 다루지 않습니다.** A가 만든 정리된 CSV 하나(5절의 스키마)를 받아 서버와 화면을 만듭니다. 그 전까지는 같은 스키마의 **가짜(DUMMY) CSV**로 개발합니다.

## 2. 과제의 필수 조건 (공지 기준, 반드시 지킬 것)

1. **범위 밖의 값을 넣거나 결과가 0건이어도 서버와 화면이 멈추지 않을 것.**
2. **다른 팀이 README만 보고 설치·실행할 수 있을 것. 인증키가 없으면 `data/sample` 폴더의 샘플 데이터로 실행될 것.**
3. **인증키는 `.env`에만 두고, 코드에 직접 적거나 GitHub에 올리지 않을 것. 올라가면 감점.**
4. 조건을 받아 결과를 돌려주는 **API 서버**와, 결과를 표·그래프로 보여 주는 **Streamlit 화면**이 있어야 합니다.
5. **AI와 함께 만든 과정**(agent에게 어떻게 요청했고 결과를 보고 무엇을 고쳤는지)을 `docs/prompts.md`에 기록합니다.
6. 다른 팀 코드·데이터를 그대로 가져오면 0점입니다.
7. 질의응답에서 **팀원 1명을 무작위로 지목**합니다. 2인 팀이라 B도 A의 데이터 파트를, A도 B의 서버 파트를 설명할 수 있어야 합니다.
8. 공개 URL 배포는 선택입니다. Streamlit 무료 배포에는 API 서버가 같이 안 올라가므로, 배포 화면은 정리된 CSV를 직접 읽어야 합니다. 4절의 "공통 계산 모듈" 설계가 이 문제를 해결합니다.

**평가 비중:** 동작 35%(교차 실행 성공, API·화면 예외 처리) / 데이터 정확성 25% / 경영적 의미 20% / 발표·질의응답 20%.
B 파트가 가장 큰 비중인 **동작 35%**를 책임집니다. 기능을 늘리기보다 "어떤 입력에도 안 멈추고, 다른 사람 PC에서 README대로 돌아가는 것"이 우선입니다.

## 6. B가 만들 것 (상세 명세)

### 6-1. `src/scoring.py` — 계산 모듈 (순수 함수)

**입지 지표 (자치구별)**
- `demand = night_weight × night_foreigners + (1 − night_weight) × day_foreigners`
  - `night_weight`: 0~1. "야간 숙박 수요 ↔ 주간 관광 수요" 중 무엇을 중시할지. 기본 0.7
- `demand_per_room = demand ÷ active_rooms`. `active_rooms == 0`이면 `demand ÷ 1`로 계산하고 `no_competition = True`로 표시
- 순위 점수(초안, A와 조정 가능): 25개 구 안에서 표준화(z-score) 후
  `score = 0.6 × z(demand_per_room) + 0.4 × z(demand)`
- 미등록 숙소 주의 표시: `day_foreigners`가 25개 구 중 상위 25%면 `caution = True`
  (미신고 숙소가 관광지 주변에 몰려 있다는 보도가 있어, 이런 구는 경쟁이 실제보다 낮게 잡혔을 수 있음)

**손익분기 (1객실 기준, 사용자 입력만으로 계산)**
- `monthly_cost = monthly_rent + other_cost`
- `breakeven_nights = ceil(monthly_cost ÷ price)`. 30을 넘으면 "한 달 내내 차도 적자" 표시
- `expected_profit = price × 30 × (occupancy_pct ÷ 100) − monthly_cost`

**필터**
- `districts`(자치구 코드 목록)가 있으면 그 구만
- `max_rooms`가 있으면 `active_rooms ≤ max_rooms`인 구만 (경쟁이 적은 곳만 보기)
- 결과가 0건이면 빈 목록과 안내 메시지

pandas DataFrame을 받아 DataFrame을 돌려줍니다. 0 나누기와 NaN에도 에러가 나지 않아야 합니다.

### 6-2. `src/data_loader.py`
- `data/processed/district_summary.csv`가 있으면 그걸, 없으면 `data/sample/district_summary.csv`를 읽고, 어느 파일을 읽었는지 함께 반환합니다. 화면 상단에 "샘플 데이터로 실행 중"을 표시하는 데 씁니다.
- `sgg_code`는 문자열로 읽습니다 (`dtype={"sgg_code": str}`).
- 필수 컬럼이 빠졌거나 25행이 아니면, 멈추지 말고 경고 메시지를 반환합니다.

### 6-3. `src/api.py` — FastAPI

| 엔드포인트 | 설명 | 파라미터 |
|---|---|---|
| `GET /health` | 서버 상태, 사용 중인 데이터 파일(processed/sample), `data_as_of` | 없음 |
| `GET /districts` | 25개 구 코드·이름 목록 | 없음 |
| `GET /rank` | 조건에 맞는 자치구 순위 | `night_weight`(0~1, 기본 0.7), `max_rooms`(선택, 0 이상), `districts`(선택, 쉼표로 구분한 코드), `top_n`(1~25, 기본 5) |
| `GET /simulate` | 손익분기·예상 월 손익 | `price`(1~2,000,000원), `occupancy_pct`(0~100), `monthly_rent`(0~10,000,000원), `other_cost`(0 이상, 기본 0), `sgg_code`(선택: 넣으면 그 구의 수요·경쟁 정보와 월세 참고값을 함께 반환) |

**예외 처리 규칙 (가장 중요)**
- 범위 밖 값 → **400 + 한국어 안내 JSON**으로 통일:
  `{"ok": false, "message": "가동률은 0~100 사이로 입력해 주세요.", "results": []}`
  (FastAPI의 `RequestValidationError` 핸들러를 등록해서 형식을 맞춥니다)
- 없는 자치구 코드 → 400 + "서울 자치구 코드가 아닙니다: 99999"
- 결과 0건 → **200** + `{"ok": true, "message": "조건에 맞는 자치구가 없습니다. 경쟁 객실 수 상한을 높여 보세요.", "results": []}`
- 데이터 파일이 아예 없음 → 503 + 안내 메시지 (서버는 계속 떠 있음)
- 정상 응답도 같은 형식: `{"ok": true, "message": "", "data_source": "processed|sample", "data_as_of": "...", "results": [...]}`

### 6-4. `app.py` — Streamlit 화면

- **탭 1: 입지 비교**
  - 입력: 자치구 다중 선택(기본 전체), 야간↔주간 가중치 슬라이더, 경쟁 객실 수 상한, 보여 줄 개수
  - 출력: 순위표, 막대그래프(점수 또는 객실당 수요), ⚠ 미등록 숙소 주의 표시
- **탭 2: 손익분기 계산**
  - 입력: 자치구(선택), 1박 요금, 예상 가동률(%), 월세, 월 기타 비용
  - 출력: 손익분기 예약일수, 예상 월 손익(적자는 빨간색), 선택한 구의 야간·주간 수요와 영업 중 숙소·객실 수
- 상단: 데이터 출처와 기준 시점, "샘플 데이터로 실행 중"(해당 시), DUMMY면 빨간 경고
- 하단 고정 문구: "1박 요금, 가동률, 월세는 사용자가 입력한 가정입니다. 경쟁 숙소는 등록 업소 기준 최소치이며, ⚠ 표시 구는 미등록 숙소가 많을 수 있습니다."
- **데이터를 가져오는 방식:** 환경변수 `API_URL`(기본 `http://localhost:8000`)로 API를 먼저 호출하고, 실패하면(연결 안 됨, 3초 타임아웃) `data_loader`와 `scoring`으로 직접 계산한 뒤 "API 서버 없이 실행 중"이라고 표시합니다. **어느 쪽이든 화면이 멈추면 안 됩니다.**
- API가 돌려준 `message`가 있으면 `st.info`나 `st.warning`으로 보여 줍니다.

## 9. 질의응답 대비: A 파트 요약 (B도 설명할 수 있어야 함)
- **수집:** 서울 열린데이터광장 OpenAPI로 도시민박업 인허가 정보를 페이지를 넘기며 수집해 `data/raw`에 저장합니다. 생활인구는 월별 CSV 파일을 내려받습니다. API는 매번 호출하지 않고 파일로 저장해 씁니다.
- **정리:** 도시민박업은 영업 중인 업소만 남기고, 소재지 주소의 "OO구"로 자치구를 붙여 업소 수·객실 수를 집계합니다. 생활인구는 행정동 코드의 앞 5자리(자치구 코드)로 묶어 합산한 뒤, 야간·주간 시간대 평균을 냅니다.
- **결합:** 두 데이터를 자치구 코드로 결합해 25행을 만듭니다.
- **건수 검증표:** 원본 − 제거(폐업·취소) = 영업 중 / 영업 중 = 자치구 매칭 성공 + 실패 / 결합 후 25개 구가 모두 남았는지. 0건이어도 0건이라고 적고 확인 방법을 남깁니다.
- **한계:** 1박 요금·가동률은 공개 데이터가 없어 사용자 입력값입니다. 미등록 숙소는 빠져서 경쟁은 등록 업소 기준 최소치입니다. 생활인구는 통신 데이터 기반 추정치입니다.
