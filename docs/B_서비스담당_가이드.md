# 명당발견 · B 서비스 담당 가이드 (v4)

> 이 파일은 B(서비스 담당) 김태현과, 김태현이 쓰는 AI 코딩 에이전트(Claude Code 등)가 함께 읽는 작업 지시서입니다.
> **에이전트를 처음 실행하면 이 파일 전체를 먼저 읽게 하세요.** 마지막 절에 첫 프롬프트 예시가 있습니다.
> 작성: 박준영(A, 데이터 담당) · 2026-11-24 기준 v4

**v2에서 바뀐 점 (11/20 제출 후 교수님 피드백 반영)**
- 1차 범위를 **도시민박업 인허가(API) + 단기외국인 생활인구(CSV)** 두 가지로 줄였습니다. 전월세 실거래가는 **여유가 있을 때 추가하는 2차 목표**입니다.
- 그래서 손익분기 계산의 월세는 **사용자가 직접 입력**합니다. 신규 호스트는 자기 집 월세를 이미 알고 있으므로 오히려 자연스러운 설계입니다.
- CSV 스키마에서 월세 컬럼이 빠졌고, `/rank`의 `max_rent` 대신 `max_listings`(경쟁 업소 수 상한)를 씁니다.

**v3에서 바뀐 점 (실제 API 데이터 확인 후)**
- 실제 데이터에서 객실 수(`STROOMCNT`)가 영업 중 업소의 46%에서 비어 있고, 자치구별 결측률이 10%~99%로 크게 달랐습니다. 그래서 **경쟁 지표는 객실 수가 아니라 영업 중 업소 수(`active_listings`)**를 씁니다.
- CSV의 `active_rooms` 컬럼이 없어지고, 참고용 `rooms_known_listings`, `rooms_known_sum`이 생겼습니다.

**v4에서 바뀐 점 (11/24 실제 데이터 정리 완료)**
- **실제 `data/processed/district_summary.csv`(25행)가 GitHub에 올라가 있습니다.** `git pull`로 받으세요. DUMMY CSV는 이제 필요 없고, 0 나누기 테스트는 테스트 코드 안에서 작은 표를 만들어 합니다(6-5).
- 실제 데이터로 돌려 보니 **영업 중 업소가 14곳뿐인 금천구가 점수 1위로 튀었습니다**(업소당 수요 210, 2위 서초구의 2배 이상). 그래서 `/rank`에 **`min_listings`(기본 50)**를 추가합니다. 기준 미만인 구는 순위에서 빼고 "검증 부족 시장"으로 따로 보여 줍니다.
- **z점수는 필터를 적용한 뒤 남은 구만으로 다시 계산합니다.** 극단값이 다른 구의 점수까지 왜곡하지 않게 하기 위해서입니다.
- A 쪽 수정 사항(질의응답 대비): 중복 제거 키를 구청코드+관리번호로 바꿨고, 생활인구 파일 형식이 섞여 있는 문제를 처리했습니다(9절).

## 2. 과제의 필수 조건 (공지 기준, 반드시 지킬 것)

1. **범위 밖의 값을 넣거나 결과가 0건이어도 서버와 화면이 멈추지 않을 것.**
2. **다른 팀이 README만 보고 설치·실행할 수 있을 것. 인증키가 없으면 `data/sample` 폴더의 샘플 데이터로 실행될 것.**
3. **인증키는 `.env`에만 두고, 코드에 직접 적거나 GitHub에 올리지 않을 것. 올라가면 감점.**
4. 조건을 받아 결과를 돌려주는 **API 서버**와, 결과를 표·그래프로 보여 주는 **Streamlit 화면**이 있어야 합니다.
5. **AI와 함께 만든 과정**(agent에게 어떻게 요청했고 결과를 보고 무엇을 고쳤는지)을 `docs/prompts.md`에 기록합니다.
6. 다른 팀 코드·데이터를 그대로 가져오면 0점입니다.
7. 질의응답에서 **팀원 1명을 무작위로 지목**합니다. 2인 팀이라 B도 A의 데이터 파트를, A도 B의 서버 파트를 설명할 수 있어야 합니다.
8. 공개 URL 배포는 선택입니다. Streamlit 무료 배포에는 API 서버가 같이 안 올라가므로, 배포 화면은 정리된 CSV를 직접 읽어야 합니다. 4절의 "공통 계산 모듈" 설계가 이 문제를 해결합니다.

**평가 비중:** 동작 35%(교차 실행 성공, API·화면 예외 처리) / 데이터 정확성 25% / 경영적 의미 20% / 발표·질의응답 20%.

## 6. B가 만들 것 (상세 명세)

### 6-1. `src/scoring.py` — 계산 모듈 (순수 함수)

**입지 지표 (자치구별)**
- `demand = night_weight × night_foreigners + (1 − night_weight) × day_foreigners`
  - `night_weight`: 0~1. "야간 숙박 수요 ↔ 주간 관광 수요" 중 무엇을 중시할지. 기본 0.7
- `demand_per_listing = demand ÷ active_listings`. `active_listings == 0`이면 `demand ÷ 1`로 계산하고 `no_competition = True`로 표시
- 순위 점수: **필터(`min_listings`, `max_listings`, `districts`)를 적용한 뒤 남은 구 안에서** 표준화(z-score) 후
  `score = 0.6 × z(demand_per_listing) + 0.4 × z(demand)`
  - z는 모표준편차(`ddof=0`)로 계산합니다. 남은 구가 1개이거나 표준편차가 0이면 z를 0으로 둡니다(0 나누기 금지).
- 검증 부족 시장 표시: `active_listings < min_listings`이면 `thin_market = True`. 이 구들은 순위에서 빠지고, 응답의 `excluded` 목록에 이름·업소 수·업소당 수요와 함께 담깁니다.
- 미등록 숙소 주의 표시: `day_foreigners`가 25개 구 중 상위 25%면 `caution = True`
  (미신고 숙소가 관광지 주변에 몰려 있다는 보도가 있어, 이런 구는 경쟁이 실제보다 낮게 잡혔을 수 있음)

**손익분기 (1객실 기준, 사용자 입력만으로 계산)**
- `monthly_cost = monthly_rent + other_cost`
- `breakeven_nights = ceil(monthly_cost ÷ price)`. 30을 넘으면 "한 달 내내 차도 적자" 표시
- `expected_profit = price × 30 × (occupancy_pct ÷ 100) − monthly_cost`

**필터**
- `districts`(자치구 코드 목록)가 있으면 그 구만
- `min_listings`(기본 **50**): `active_listings ≥ min_listings`인 구만 순위에 넣음. 업소가 너무 적은 구는 업소당 수요가 분모 효과로 튀고, 수요가 검증되지 않은 시장일 수 있음. 0을 넣으면 전체 25개 구를 비교함
- `max_listings`가 있으면 `active_listings ≤ max_listings`인 구만 (경쟁이 적은 곳만 보기)
- `min_listings > max_listings`이면 400 + "최소 업소 수가 최대 업소 수보다 클 수 없습니다." 
- 결과가 0건이면 빈 목록과 안내 메시지

pandas DataFrame을 받아 DataFrame을 돌려줍니다. 0 나누기와 NaN에도 에러가 나지 않아야 합니다.

### 6-2. `src/data_loader.py`

- 필수 컬럼이 빠졌거나 25행이 아니면, 멈추지 말고 경고 메시지를 반환합니다.

### 6-3. `src/api.py` — FastAPI

| 엔드포인트 | 설명 | 파라미터 |
|---|---|---|
| `GET /health` | 서버 상태, 사용 중인 데이터 파일(processed/sample), `data_as_of` | 없음 |
| `GET /districts` | 25개 구 코드·이름 목록 | 없음 |
| `GET /rank` | 조건에 맞는 자치구 순위 | `night_weight`(0~1, 기본 0.7), `min_listings`(0 이상, 기본 50), `max_listings`(선택, 0 이상), `districts`(선택, 쉼표로 구분한 코드), `top_n`(1~25, 기본 5) |
| `GET /simulate` | 손익분기·예상 월 손익 | `price`(1~2,000,000원), `occupancy_pct`(0~100), `monthly_rent`(0~10,000,000원), `other_cost`(0 이상, 기본 0), `sgg_code`(선택: 넣으면 그 구의 수요·경쟁 정보와 월세 참고값을 함께 반환) |

**예외 처리 규칙 (가장 중요)**
- 범위 밖 값 → **400 + 한국어 안내 JSON**으로 통일:
  `{"ok": false, "message": "가동률은 0~100 사이로 입력해 주세요.", "results": []}`
  (FastAPI의 `RequestValidationError` 핸들러를 등록해서 형식을 맞춥니다)
- 없는 자치구 코드 → 400 + "서울 자치구 코드가 아닙니다: 99999"
- 결과 0건 → **200** + `{"ok": true, "message": "조건에 맞는 자치구가 없습니다. 경쟁 업소 수 상한을 높여 보세요.", "results": []}`
- 데이터 파일이 아예 없음 → 503 + 안내 메시지 (서버는 계속 떠 있음)
- 정상 응답도 같은 형식: `{"ok": true, "message": "", "data_source": "processed|sample", "data_as_of": "...", "results": [...], "excluded": [...]}`
  - `excluded`: `min_listings` 때문에 빠진 구 목록(`sgg_name`, `active_listings`, `demand_per_listing`). 빠진 구가 없으면 빈 목록

### 6-4. `app.py` — Streamlit 화면

- **탭 1: 입지 비교**
  - 입력: 자치구 다중 선택(기본 전체), 야간↔주간 가중치 슬라이더, **최소 업소 수(기본 50)**, 경쟁 업소 수 상한, 보여 줄 개수
  - 출력: 순위표, 막대그래프(점수 또는 업소당 수요), ⚠ 미등록 숙소 주의 표시
  - 순위표 아래 접는 상자(`st.expander`): "검증 부족 시장 (업소 N곳 미만)" — 빠진 구와 업소 수, 업소당 수요. 설명 문구: "업소가 적어 업소당 수요가 크게 나오지만, 수요가 숙박으로 이어지는지 검증되지 않았습니다."
- **탭 2: 손익분기 계산**
  - 입력: 자치구(선택), 1박 요금, 예상 가동률(%), 월세, 월 기타 비용
  - 출력: 손익분기 예약일수, 예상 월 손익(적자는 빨간색), 선택한 구의 야간·주간 수요와 영업 중 업소 수 (객실 수는 "정보가 있는 업소 기준 참고값"으로 표시)
- 상단: 데이터 출처와 기준 시점, "샘플 데이터로 실행 중"(해당 시), DUMMY면 빨간 경고
- 하단 고정 문구: "1박 요금, 가동률, 월세는 사용자가 입력한 가정입니다. 경쟁 숙소는 등록 업소 기준 최소치이며, ⚠ 표시 구는 미등록 숙소가 많을 수 있습니다."
- **데이터를 가져오는 방식:** 환경변수 `API_URL`(기본 `http://localhost:8000`)로 API를 먼저 호출하고, 실패하면(연결 안 됨, 3초 타임아웃) `data_loader`와 `scoring`으로 직접 계산한 뒤 "API 서버 없이 실행 중"이라고 표시합니다. **어느 쪽이든 화면이 멈추면 안 됩니다.**

## 9. 질의응답 대비: A 파트 요약 (B도 설명할 수 있어야 함)
- **수집:** 서울 열린데이터광장 OpenAPI로 도시민박업 인허가 정보를 페이지를 넘기며 수집해 `data/raw`에 저장합니다. 생활인구는 월별 CSV 파일을 내려받습니다. API는 매번 호출하지 않고 파일로 저장해 씁니다.
- **정리:** 도시민박업은 영업 중인 업소만 남기고(9,784건 중 영업/정상 7,833곳, 폐업·취소·휴업 제거), 소재지 주소의 "OO구"로 자치구를 붙여 업소 수를 집계합니다. 객실 수는 구청마다 입력 여부가 달라(결측률 10%~99%) 경쟁 지표에서 제외했습니다. 생활인구는 행정동 코드의 앞 5자리(자치구 코드)로 묶어 합산한 뒤, 야간·주간 시간대 평균을 냅니다.
- **중복 제거:** 관리번호(MGTNO)는 구청마다 따로 매겨져서 서울 전체에서는 겹칩니다. 관리번호만 기준으로 중복을 지우면 서로 다른 업소 6,930건이 사라지기 때문에, **구청코드(OPNSFTEAMCODE)+관리번호**를 고유키로 썼습니다. 이 기준으로 진짜 중복은 0건입니다. 에어비앤비 숙소 페이지의 등록번호를 대조하다가 이 문제를 발견했습니다.
- **생활인구 파일 형식:** 2026년 10월 일별 파일 31개 중 27개는 데이터 줄이 세미콜론으로, 4개는 쉼표로 구분돼 있습니다. 줄마다 구분자를 판단해 읽었고, 31개 × 10,248행 = 317,688행으로 건수가 맞습니다.
- **결합:** 두 데이터를 자치구 코드로 결합해 25행을 만듭니다. 업소 수 합계는 7,833으로 정리 후 건수와 같습니다.
- **결과 요약 (야간 가중치 0.7):** 마포구에 서울 도시민박의 27%(2,123곳)가 몰려 있어 업소당 수요가 7.1로 가장 낮습니다. 업소 50곳 이상인 구 중에서는 서초구(91.4)·중구(53.1)·강남구(43.0) 순으로 높습니다. 다만 중구·강남구는 호텔이 많고, 금천·구로·영등포는 출장 등 비관광 수요가 섞였을 가능성이 있다는 점은 한계입니다.
- **건수 검증표:** 원본 − 제거(폐업·취소) = 영업 중 / 영업 중 = 자치구 매칭 성공 + 실패 / 결합 후 25개 구가 모두 남았는지. 0건이어도 0건이라고 적고 확인 방법을 남깁니다.
- **한계:** 1박 요금·가동률은 공개 데이터가 없어 사용자 입력값입니다. 미등록 숙소와 공유숙박 실증특례 숙소는 이 인허가 데이터에 없어서, 경쟁은 등록 업소 기준 최소치입니다. 호텔과의 경쟁은 반영하지 않았습니다. 생활인구는 통신 데이터 기반 추정치입니다.

